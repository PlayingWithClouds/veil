# Android app

Native Kotlin + Jetpack Compose (Material 3) plus the Go backend on the phone. Gradle root `apps/mobile` (Kotlin DSL, catalog `gradle/libs.versions.toml`, one `:app` module, package `com.playingwithclouds.veil`). `local.properties` (gitignored) must point `sdk.dir` at an SDK with platform 37.

Commands (in `apps/mobile`): `bun run build` (arm64 backend into `jniLibs` + release plugin bundles into `assets/plugins`), `bun run apk` (+ `./gradlew assembleDebug` → `app/build/outputs/apk/debug/app-debug.apk`), `bun run android` (+ install, launch), `bun run test` (JVM).

## Rules

- No WebView, no Capacitor. One exception, never for showing content: `solver/WebSolver` is the phone's FlareSolverr. `SolverServer` (started before the backend) answers FlareSolverr's `request.get` on a loopback port that the backend gets as `FLARESOLVERR_URL`; a hidden WebView loads the page, waits until Cloudflare's check is gone and returns the rendered HTML (the clearance cookie stays in the WebView, bound to the IP). When the check wants a tap for 12 s and the app is in front, `ChallengeActivity` shows the page until it clears.
- Backend is pure Go (`CGO_ENABLED=0`) at `jniLibs/arm64-v8a/libveil.so`, the only place Android executes app files from.
- `VeilApi` is the only place that builds the Apollo client.
- Backend-built URLs carry `PUBLIC_URL` (default localhost): pass them through `ServerSettings.backendUrl()`, `imageUrl()` or `RemoteImage` (proxies via `/api/img`) so loopback is rebased (`BackendUrls`).
- Screens use only `ui/theme` tokens and `ui/design` components: no raw colours, shapes, `sp`, or literal dp in paddings/gaps (`DesignTokenUsageTest`).
- No colour accent: `VeilColors.accent` is white and marks selection and progress (the owner found the web's violet too loud on the phone); reasons on cards are muted; the only hue is `live` pink; things floating over content use blurring `glass` (the tab bar; top bars via `GlassTopBarLayout` + `LocalTopBarInset`, see-through until content scrolls under them: tab screens with `TabTopBar`, every other screen with `DetailScreen`; the video and cam room pages have no bar, Back sits in the player's controls via `PlayerExtras.onBack`; sheets blur behind their window where the phone supports it); one glow lights the app as on the web: pages call `ShowAmbientGlow(featured picture)`, the shell draws `AmbientGlow` behind the see-through screens (theme `background` is transparent; the root paints the canvas); buttons, pills and tags look like the Library's `FeedChip`s (flat `surfaceHigh`, `VeilShapes.small` corners, white when selected or primary; the owner prefers them to glass capsules); switches, checks and round icon buttons stay `glassControl`. Every search starts from a magnifier at the right of the top bar: tapped, `BarSearchField` takes the bar's place (`DetailScreen(searchBar = …)`), Back closes it; only the Search screen has its box in the page.
- One package per screen under `ui/`, `ViewModel` + `StateFlow` + `LoadState`, endless lists via `ui/paging/PagedList`.
- Media items carry only "Playing" + app name, no artwork; notifications use `NeutralNotifications` wording, `VISIBILITY_SECRET`.
- Habits (`habits/`): there's no O button; `FinishGuesser` logs an O (`data.inferred: true`, which the engine weighs at `inferredEventShare`) when the app is left within 5 min of a video playing after 3+ min watched. `SubscriptionCheckWorker` (WorkManager, every 6 h, battery not low, Wi-Fi only if `HabitPreferences.wifiOnly`) runs every follow, then `planNudge` learns usual times (`UsualTimes`: half-hour slots of the week from `o` and `view` events) and schedules `NudgeWorker` 15 min before the next one: one notification a day at most, none if the app was opened that day, titled only "Reminder", dot icon, hidden on the lock screen. Settings → Background has both switches.
- Incognito: `AppServices.events` (the `EventLog`: impressions, watch progress, likes, O, searches) sends nothing. New tracking must go through the event log or respect it.
- The app keeps its real name until the owner picks a disguise.
- The backend has no ffmpeg; frames come only from the app.
- `FLAG_SECURE` blacks out screenshots, `adb screencap` and recordings; turn "Hide in recents and screenshots" off to take them.

## Backend on device

- `backend/EmbeddedBackend.kt` starts it from `VeilApplication` on `127.0.0.1:47831`, `DATA_DIR` in app storage; extracts `assets/plugins` as `PLUGIN_SEED_DIR` once per install/update (`PluginSeeder`); keeps `DNS_SERVERS_FILE` current; restarts on crash; logs to tag `VeilBackend`. Env/DNS rules in `BackendEnvironment` (unit tested).
- Another server can be saved in Settings (`ServerSettings`, `ServerForm`); saving restarts the app. `BootGate` (`ui/VeilApp.kt`) waits for `/health`, falls back to the server form.
- GraphQL: Apollo Kotlin from `apps/backend/internal/api/graphql/schema/*.graphql`; operations in `app/src/main/graphql/com/playingwithclouds/veil/*.graphql`; `data/*Repository.kt` map to UI models. Subscriptions (search) go over Apollo's WebSocket transport (`VeilApi`).

## Scene model (`scenes/`, Settings → Scene model)

The classifier from the `nsfw-scene-recognition` repo (MobileNetV4-S fine-tune) runs on the phone with ONNX Runtime (`SceneClassifier`). Without a model everything below stays hidden or off; Shorties still work from clips, segments and replays.

- Bundled: the Gradle task `bundleSceneModel` copies the newest export (`../../../nsfw-scene-recognition/runs/<export>/onnx`, by manifest date; or `-PsceneModelDir=` / `VEIL_SCENE_MODEL_DIR`) as `assets/scene-model/` (manifest.json + the graphs it names); without one the build goes on without a model. `SceneModelStore` installs it on first start and when an update brings another export (`BundledModel.isDue`: versions are content hashes, so "different from the last bundled one" stands for newer); a model installed from a URL or zip stays until then. Settings → Scene model: "Use the bundled model".
- Install (`SceneModelStore`): a URL to `model.json` (graph files resolved beside it) or to a zip of the three files, or a zip picked from storage; unpacked into `files/scene-model-incoming`, checked, then swapped into `files/scene-model`. A failed install keeps the old model.
- export.py actually writes `manifest.json` (`frame_model`, `temporal_model`, `input.shape/mean/std`, `sample_fps`, `heads` keyed by name with `kind` softmax|sigmoid and `in` frame|temporal): `SceneModelManifest.parseExport` reads it (context heads and close-up shots filled in from taxonomy.yaml; version from the content's hash) and the store renames it to `model.json`. Outputs are read by name, so key order doesn't matter.
- `model.json` contract (the app's own format; `SceneModelManifest` reads it, refusing other `format`s):
  - `format` 1; `version` (export name: a new one rescans everything); `taxonomyVersion`.
  - `input`: `size` (square side), `mean` and `std` (RGB, 0..1 scale). Frames are centre-cropped, scaled, CHW.
  - `frame`: `file`, `input` (`images`, N×3×size×size), `embedding` (first output, N×D), `heads` = the other outputs in order (N×labels logits).
  - `temporal` (optional): `file`, `input` (`embeddings`, S×window×D), `window`, `frameSeconds` (spacing it was trained on), `heads` (outputs, logits for each window's last frame).
  - `heads`: `[{name, kind: exclusive|multi, title?, context?, condition?: {head, label}, labels: [{name, title?, deprecated?}]}]` in taxonomy.yaml order; `closeupShots`: `shot` labels on which context heads aren't judged from one frame.
- Labels → tags in one place, `SceneLabels` (site-style names: `oral_intensity.regular` → "Blowjob", `position.doggy` → "Doggystyle"; unknown labels use their title or name in words; position kneeling/lying_oral/side_by_side/other and camera angles other than POV never become segments). Heads that become segments: oral_intensity, act, position, fetish, climax, camera.
- Scan (`SceneScanner`, `SceneScanWorker` via `SceneScans`): WorkManager every 3 h, only while charging, battery not low, Wi-Fi when `HabitPreferences.wifiOnly`; up to 25 videos a run, favourites → collections (watchlist, queue, own) → recently watched → recommendations, skipping those scanned with the installed model version (prefs `sceneScans`). A frame every 2 s (< 10 min), 3 s (< 40 min), 4 s beyond, at most 900, grabbed from the stream with Media3's `FrameExtractor` (closest key frame, decoded at 288 px; local files first, then `play(url)`; `fetchVideo` first so stubs have streams). Batches of 8 through `frame.onnx`, windows of the embeddings through `temporal.onnx`; image and video readings averaged per head (`FrameProbabilities`); `SceneSegments` (a port of `nsr/segments.py`: hysteresis 0.6/0.4, gaps ≤ 2 frames closed, runs ≥ 3 frames; exclusive heads by 5-frame smoothed argmax ≥ 0.4) → `replaceAiSegments`, which never touches user or plugin segments.
- Open video (`OpenVideoScan`, started by `VideoViewModel.scanScenes` 5 s into playback): when the video isn't scanned with the installed model, the playing stream is scanned right away from the playhead (then wrapping to the start) at `ScanPace.BESIDE_PLAYBACK` (batches of 4, a background-priority thread, pauses; ONNX Runtime on 2 threads); `ScanTimeline` holds frames in any order and reads each frame's temporal window once it's complete, so a full scan equals one from the start. The player's sections fill in per batch (`SceneSections.withScanned`), saved every quarter and at the end (then marked scanned); leaving the page cancels. No charging needed; skipped in battery saver, and on mobile data when Wi-Fi only is on unless it plays a local copy (`OpenScanPolicy`), since grabbing frames reads the stream about once more.
- Player sections: `SceneSections.chapters` turns ai segments into chapters: same label within 12 s joined, at most two labels per section ("Blowjob · POV"), nothing under 20 s (folded into the longer neighbour), untitled markers where nothing is recognised; ai sections overlapping a user or plugin segment are dropped. `MarkerChips` skip the untitled ones.
- Liked scenes: the scene labels said yes to in Your taste, i.e. tags of ai segments whose latest `like` is +1 (backend `likedSceneTags` query, `recommend.LikedSceneTags`; `SceneRepository.likedTags`). They drive the compilation, the shorts (backend) and card previews. The old `likedSceneTags` setting is turned into likes once at backend start.
- Your taste (`ui/taste`, drawer → Your taste, `taste` query): `TasteSections` splits it into What you're into (scene labels said yes to, or scored > 0 with certainty ≥ 0.3; evidence sentences from `recommend/scenelabels.go`; play = `openCompilationOf(tag)`), Performers / Studios / Sites, Things you avoid, Not sure yet (unanswered, least certain labels). Yes / Not really / Undo send a `like` of 1 / -1 / 0 at once via `recordEvent` (`TasteRepository.answer`; a site has no subject, `data.site`), so they count while incognito; only a subject's latest like counts.
- Search by what's in a video: `FilterInput.sceneTagIds` (all labels, videos/audio; no other sort = most matching seconds first). Filters sheet "What's in it" (`sceneLabelCounts`); typed words naming a label become labels (`SceneLabelWords`), the rest goes to the sites; Search lists "In your library" (`videos(filter:)`) above the site results, and opens a result at its first matching segment (`SceneRepository.firstSceneStart` → `openVideoAt`).
- Compilation (`ui/compilation`, Settings → Play compilation): `CompilationPlanner` cuts each video to its liked stretches (joined within 6 s, ≥ 8 s, ≤ 150 s, 1 s lead-in); videos from the queue first (`sceneMatches(videoIds:)`), then `sceneMatches` most matching seconds first; a playlist of `clippedMediaSource`s that jumps by itself, prepared 3 clips ahead, the clips listed under the player (playing one highlighted, tap jumps). Over the queue (video page's Compilation pill, the queue sheet, Home's "Compilation of your queue" chip): `CompilationSheet` picks the liked scenes or labels for this one (chips from the model's heads), queue order or shuffle (all clips mixed), shortest clip 8/15/30 s → route `compilation?…&queue=1&order=&min=`, the playing video and the queue only.
- Cover tags (`CoverLabels`): every `VideoCard` cover is read once per URL and model version (Coil's cached bitmap, cached in `cacheDir/cover-labels`); `ImpressionLogger` sends tags ≥ 0.5 as `data.coverTags` on impressions (waiting up to 2 s) and choices (when read).
- Card previews (`CardPreview`): with ai segments, 4–6 moments of 2.5 s from the liked scenes first (`PreviewMoments`), seeking in the stream, even over the site's clip; else the site's clip; else `previewFrames` as a flipbook.

## Privacy (Settings → Privacy, `ui/settings/PrivacySection.kt`)

Stored by `privacy/PrivacyPreferences` (StateFlows over SharedPreferences), applied by `MainActivity` (a `FragmentActivity` for biometrics).

- Recents/screenshots: `FLAG_SECURE` while "Hide in recents and screenshots" (default on) or app lock is on.
- App lock (`AppLock`, `LockPolicy`, `PinHasher`, `ui/privacy/LockScreen`): 4–8 digit PIN, salted PBKDF2, optional biometrics (`BiometricUnlock`), delay (immediate, 1, 5 min), throttled from the 5th wrong try. Drawn over the app in `VeilApp`; cold start is locked. Lock and panic pause playback via `PrivacyEvents.pauseRequests` (`rememberScenePlayer`).
- Panic (`PanicController`, `PanicDetectors`): face-down (foreground only) or two-finger double tap (`MainActivity.dispatchTouchEvent`, never consumed) → pause, lock if set, go home.
- Disguise: one `activity-alias` per entry (`.alias.DefaultAlias` real; `Files`/`Gallery`/`Notes`/`Calculator` share `@mipmap/ic_disguise`); `Disguises.apply` enables one. Labels in `strings.xml`.
- `NeutralMedia`: no media session or notification producer exists yet.
- Incognito: in memory, ends with the process or by tapping "You're incognito". Likes, ratings, lists, downloads still count; a first visit still stamps `detail_fetched_at` (read as a click).
- Encrypted downloads: see storage rules. `privacy/BlobKeyProvider` generates the key, seals it with an Android Keystore AES key, passes it via `BackendEnvironment`, replaces it if unopenable (old blobs then unreadable). "Encrypt downloads" (default on) applies after restart.
