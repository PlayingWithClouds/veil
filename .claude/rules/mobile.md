# Android app

Native Kotlin + Jetpack Compose (Material 3) plus the Go backend on the phone. Gradle root `apps/mobile` (Kotlin DSL, catalog `gradle/libs.versions.toml`, one `:app` module, package `com.playingwithclouds.veil`). `local.properties` (gitignored) must point `sdk.dir` at an SDK with platform 37.

Commands (in `apps/mobile`): `bun run build` (arm64 backend into `jniLibs` + release plugin bundles into `assets/plugins`), `bun run apk` (+ `./gradlew assembleDebug` → `app/build/outputs/apk/debug/app-debug.apk`), `bun run android` (+ install, launch), `bun run test` (JVM).

## Rules

- No WebView, no Capacitor.
- Backend is pure Go (`CGO_ENABLED=0`) at `jniLibs/arm64-v8a/libveil.so`, the only place Android executes app files from.
- `VeilApi` is the only place that builds the Apollo client.
- Backend-built URLs carry `PUBLIC_URL` (default localhost): pass them through `ServerSettings.backendUrl()`, `imageUrl()` or `RemoteImage` (proxies via `/api/img`) so loopback is rebased (`BackendUrls`).
- Screens use only `ui/theme` tokens and `ui/design` components: no raw colours, shapes, `sp`, or literal dp in paddings/gaps (`DesignTokenUsageTest`).
- No colour accent: `VeilColors.accent` is white and marks selection and progress (the owner found the web's violet too loud on the phone); reasons on cards are muted; the only hue is `live` pink; things floating over content use blurring `glass` (the tab bar; top bars via `GlassTopBarLayout` + `LocalTopBarInset`, see-through until content scrolls under them: tab screens with `TabTopBar`, every other screen with `DetailScreen`; the video and cam room pages have no bar, Back sits in the player's controls via `PlayerExtras.onBack`; sheets blur behind their window where the phone supports it); one glow lights the app as on the web: pages call `ShowAmbientGlow(featured picture)`, the shell draws `AmbientGlow` behind the see-through screens (theme `background` is transparent; the root paints the canvas); buttons, pills and tags look like the Library's `FeedChip`s (flat `surfaceHigh`, `VeilShapes.small` corners, white when selected or primary; the owner prefers them to glass capsules); switches, checks and round icon buttons stay `glassControl`. Every search starts from a magnifier at the right of the top bar: tapped, `BarSearchField` takes the bar's place (`DetailScreen(searchBar = …)`), Back closes it; only the Search screen has its box in the page.
- One package per screen under `ui/`, `ViewModel` + `StateFlow` + `LoadState`, endless lists via `ui/paging/PagedList`.
- Media items carry only "Playing" + app name, no artwork; notifications use `NeutralNotifications` wording, `VISIBILITY_SECRET`.
- Habits (`habits/`): there's no O button; `FinishGuesser` logs an O (`data.inferred: true`, which the engine weighs at `inferredEventShare`) when the app is left within 5 min of a video playing after 3+ min watched. `SubscriptionCheckWorker` (WorkManager, every 6 h, battery not low, Wi-Fi only if `HabitPreferences.wifiOnly`) runs every follow, then `planNudge` learns usual times (`UsualTimes`: half-hour slots of the week from `o` and `view` events) and schedules `NudgeWorker` 15 min before the next one: one notification a day at most, none if the app was opened that day, titled only "Reminder", dot icon, hidden on the lock screen. Settings → Background has both switches.
- Incognito: `AppServices.events` (the `EventLog`: impressions, watch progress, likes, O, searches) sends nothing. New tracking must go through the event log or respect it.
- The app keeps its real name until the owner picks a disguise.
- The backend has no ffmpeg; frames come only from the app.
- `FLAG_SECURE` blacks out screenshots, `adb screencap` and recordings; turn "Hide in recents and screenshots" off to take them.

## Backend on device

- `backend/EmbeddedBackend.kt` starts it from `VeilApplication` on `127.0.0.1:47831`, `DATA_DIR` in app storage; extracts `assets/plugins` as `PLUGIN_SEED_DIR` once per install/update (`PluginSeeder`); keeps `DNS_SERVERS_FILE` current; restarts on crash; logs to tag `VeilBackend`. Env/DNS rules in `BackendEnvironment` (unit tested).
- Another server can be saved in Settings (`ServerSettings`, `ServerForm`); saving restarts the app. `BootGate` (`ui/VeilApp.kt`) waits for `/health`, falls back to the server form.
- GraphQL: Apollo Kotlin from `apps/backend/internal/api/graphql/schema/*.graphql`; operations in `app/src/main/graphql/com/playingwithclouds/veil/*.graphql`; `data/*Repository.kt` map to UI models. Subscriptions (search) go over Apollo's WebSocket transport (`VeilApi`).

## UI

- Every screen mirrors its web page and reads what the web's `apps/web/src/lib/*.ts` reads (named in each bullet); when the web changes how a page loads or logs, change the phone alike. Screens never build routes: `AppNavigator` (`ui/Routes.kt`) has an `open…` per destination.
- `ui/VeilShell.kt`: side menu `ui/MainDrawer.kt` (`Destination` entries in Watch / Library / You as the web's `navLinks`, Settings at the bottom; ☰ `MenuButton` via `LocalOpenDrawer` or a left-edge swipe on the tabs) over Home, Cams, Library in a `HorizontalPager` (`tabs` route) changed only by the small centred floating bar `ui/FloatingNavBar.kt` (glass, hides on scroll down), so the edge swipe stays the drawer's. Tab screens start with `TabTopBar` (☰, wordmark or title, search).
- Home opens on `HomeHero` (`ui/home/HomeHero.kt`): one recommendation edge to edge under the see-through bar, its preview looping, Play. The hero comes from the best 12 recommendations: with a preview, not the last open's hero (`home` prefs), a cover with one or two faces when Android's `FaceDetector` finds them within 1.5 s (`CoverFaces.kt`); the rest of the pool is shuffled into the top picks, faces first, on every load. Then `LiveFacesRow` (live rooms as pink-ringed `CamAvatar`s), then the web's rows. The reasons (anticipation, novelty, faces, low friction) are from research summarised when this was built; keep it free of streaks, autoplay-next and fake urgency.
- Previews (`ScenePreview`) are silent unless headphones are in (`rememberHeadphonesConnected`) and the preview allows sound (only the hero and the video page's); full-width feed cards scrub their preview while a finger drags across the cover. The video page shows the card's cover and preview at once (`VideoRepository.card`, a library read that logs nothing) until the stream plays.
- Home (`ui/home`) mirrors the web home (`apps/web/src/lib/home.ts`, `HomeRows.svelte`): top picks as a snapping row of large `VideoCard`s (the one in front plays its preview), Continue watching, Live now, Continue reading, Stories, Audio, Performers, then More for you last as full-width cards that never end (`recommendations(kinds: video)` paged by offset, then the library newest first). Rows load on their own (`HomeRepository`, `Home.graphql`) and hide while empty; pull to refresh. Cards in `ui/components/MediaCards.kt`, rows in `Shelf`, seen cards via `TrackShown` → `ImpressionLogger` (`recordEvents`, surfaces `home` / `continue` as on the web).
- Cams (`ui/cams`, mirrors the web's `cams.ts`): the Cams tab is `CamsScreen("")` (top picks from `camRecommendations`, your rooms = followed + auto-recorded, running recordings, then the live grid with gender / order / site / tag chips); its magnifier searches live rooms (`CamQuery.text`, the web's `/cams?q=`) or, switched to Recorded, the cam-show sites (`searchResults(content: "cam-shows")`); a room's tag opens `CamsScreen(tag)` as a detail screen. Follows go through `followRecord` / `unfollow` (targetKind `camModel`); finished recordings are videos (`camModel.recordings`). `CamRoomScreen` plays `watchCam` in the player's live mode and logs `view` + `progress {watched}` like the web's `trackRoomWatch`. Live is `VeilColors.live` pink, REC red.
- Library tab (`ui/library`, the web's library page plus Liked and Favourites): Watchlist / Liked (`liked(kind: video)`, from the event log; long press logs a thumbs down) / Favourites (favourite videos then galleries, long press unfavourites) / Queue / Collections / Downloads as a scrolling `FeedChip` row (six don't fit a segmented control), each loaded the first time it shows; long press a card to remove it (`CollectionEntries`); `CollectionScreen` for one collection; downloads poll while one runs. Data in `LibraryRepository` (`builtInCollection`, `collections`, `downloads`).
- Video cards: a long press opens `VideoActionsSheet` (the web's `recordActions.ts`: Play next, Add to collection, favourite, Not interested = thumbs down through the event log, block the video / first three performers / studio, Open on the site in the browser via the card's first `sources` url) unless the list passes its own `onLongClick` (Library: remove). Not interested and blocks hide cards at once via `HiddenRecords`, like the web's `hiddenRecords`.
- Search filters (`data/SearchFilter.kt`, ports of the web's `libraryFilter.ts` and `siteStyles.ts`): chip row under the box (Filters, hidden tags, recent searches) and the Filters sheet; the filter goes to `searchResults(filter:)`, its sites as `sources`. Site choices are enabled, available video plugins only: sites needing FlareSolverr (missav, spankbang) can't run on the phone and are left out there and in Plugins.
- Search (`ui/search`, the web's `search.ts`): the `searchResults` subscription over Apollo's WebSocket transport, one page at a time, each site's batch added as it comes (videos + performers), next page on scroll until every site is exhausted; recent searches from `recentSearches` while the box is empty; a submit logs a `search` event (no subject).
- People (`ui/people`): `MembersScreen` lists performers or studios (name filter, debounced); `PersonScreen` is one performer (opened with `fetchPerformer`, which reads their site pages like the web) or studio: header with facts, Favourite, Subscribe (`followRecord` / `followOf` / `unfollow`), bio, tags, a galleries row and their videos paged (`videos(filter: performerIds|studioIds)`) with the search's `FilterChipRow`/`FilterSheet` and the bar's search box. Pull down reads every site page again (`fetchPerformer(refresh: true)`). ⋯ has Edit (performers: `PerformerEditSheet`, the desktop's `PerformerEditor` fields) and Block (Undo, then the page closes). Blocked videos, performers and studios are listed in Library → Blocked (`userStates(blocked: true)`) with Unblock. Merging and face matches are web-only.
- Transitions in `ui/PageTransitions.kt`; back via navigation-compose.
- Video page (`ui/video`, mirrors the web's video page): `fetchVideo` (`VideoRepository.open`) reads the source pages; local files play first, else site streams resolved by `play(url)`, the next source when one fails (`VideoViewModel`); resume from `userState.progress` unless ≥ 95 % watched. Under the player: title and facts, actions (like / dislike with Undo / favourite / O / watchlist / download, as the web's `VideoActions`), 5-star rating (0..10), source pills, people, tags, description, Up next as the web's `relatedFeed.ts` (library `related` → `siteRelated` pages after `fetchVideo` settled → quoted site search per performer and studio name → recommendations, surface `related`).
- Playback: Media3 ExoPlayer (`ui/video/VideoPlayer.kt`), HLS and progressive, fullscreen with landscape lock (vertical videos stay portrait, `rememberFullscreenState`). Watching is logged like the web's `watchLog.ts` (`WatchLog.kt`: progress every 15 s played and on pause, `heatSpan` per stretch, `finish`, one session id per page).
- Controls look like YouTube's (`PlayerControls`): an even `playerDim` over the video; top right picture-in-picture, related, settings; three round `OverlayRoundButton`s in the middle (back 10 s / play / forward 10 s, frame steps while paused); time · current chapter bottom left, fullscreen bottom right; the seek bar along the video's bottom edge inline, lifted in fullscreen, split into chapters at the markers, played part and thumb in `playerProgress` red (the one hue beside `live`); a thin red line while hidden. Hold for 2×, swipe up for fullscreen, swipe down to leave it.
- Player extras (`ui/video`): `PlayerSettings` gear (speed 0.25–2×, quality, A–B loop, zoom to fill, PiP privacy) kept by `PlayerOptions` (loop per page; zoom, PiP privacy in `player` prefs; helpers in `PlayerMath`). Frame step while paused (`Player.stepFrame`). `MarkerChips` + seek-bar notches from the video's segments. PiP on leaving (auto from Android 12) or by button, blurred by default (`PictureInPicturePrivacy`), closing pauses. Headphone unplug pauses. Fullscreen: swipe up for the related panel.
- Galleries (`ui/galleries`, the web's `galleries.ts`): `GalleriesScreen` (Recently viewed, Favourites rows, then the feed: gallery `recommendations`, then the library newest first, then `browse` of the gallery sites in turns, as the web's `galleryFeed`; the magnifier searches the gallery sites with the search's `FilterChipRow`/`FilterSheet` (`forVideos = false`: sites, rating, not viewed, favourites, hidden tags from `mediaTagCounts(kind: gallery)`)); `GalleryScreen` opens with `fetchGallery` (logs `view`): facts, Favourite, the linked video, performers, `RatingStars`, tags, photos in a 2-column staggered grid at their own ratio (tap → `ImageViewer`), related galleries.
- Stories and audio (`ui/media`, the web's `media.ts`): lists with Continue reading / listening rows; `StoryScreen` (`fetchMedia` story: chapters as contents, branches indented) and `StoryReaderScreen` (`readChapter`, next chapter or the choices at the end; the place is saved as `progress {position}` = chapter position + fraction, see `data/StoryReading.kt`, a port of `storyReading.ts`); `AudioScreen` plays the first stream `play(url)` resolves in the shared player with `PlayerSeekBar`, logged through `WatchTracking` as kind audio.
- Categories, tags, taste, plugins: `CategoriesScreen` (`categoryTiles`, grouped, empty ones hidden); a category or a tag opens `ScopedVideosScreen` (`videos(filter: categoryIds | includeTagIds)`); `TasteScreen` (`taste`); `PluginsScreen` (switch, Update all, install packages; settings and site logins are web-only).
- Not rebuilt (old versions in git history before the reset): the Shorts-style preview feed, face identification ("Who is this?"), merging, the play queue's auto-advance.
- Design kit: Settings → Design kit (`ui/designkit`). Tokens: `VeilColors`, `VeilSpacing` (16 dp `gutter`), `VeilShapes`, `Theme.kt`, `VeilType`. Components: buttons, pills (flat `FeedChip`), headers, surfaces, glass, `SkeletonBlock` (loading stand-ins under the real rows' list keys), `bleed`/`gutterPadding`.

## Privacy (Settings → Privacy, `ui/settings/PrivacySection.kt`)

Stored by `privacy/PrivacyPreferences` (StateFlows over SharedPreferences), applied by `MainActivity` (a `FragmentActivity` for biometrics).

- Recents/screenshots: `FLAG_SECURE` while "Hide in recents and screenshots" (default on) or app lock is on.
- App lock (`AppLock`, `LockPolicy`, `PinHasher`, `ui/privacy/LockScreen`): 4–8 digit PIN, salted PBKDF2, optional biometrics (`BiometricUnlock`), delay (immediate, 1, 5 min), throttled from the 5th wrong try. Drawn over the app in `VeilApp`; cold start is locked. Lock and panic pause playback via `PrivacyEvents.pauseRequests` (`rememberScenePlayer`).
- Panic (`PanicController`, `PanicDetectors`): face-down (foreground only) or two-finger double tap (`MainActivity.dispatchTouchEvent`, never consumed) → pause, lock if set, go home.
- Disguise: one `activity-alias` per entry (`.alias.DefaultAlias` real; `Files`/`Gallery`/`Notes`/`Calculator` share `@mipmap/ic_disguise`); `Disguises.apply` enables one. Labels in `strings.xml`.
- `NeutralMedia`: no media session or notification producer exists yet.
- Incognito: in memory, ends with the process or by tapping "You're incognito". Likes, ratings, lists, downloads still count; a first visit still stamps `detail_fetched_at` (read as a click).
- Encrypted downloads: see storage rules. `privacy/BlobKeyProvider` generates the key, seals it with an Android Keystore AES key, passes it via `BackendEnvironment`, replaces it if unopenable (old blobs then unreadable). "Encrypt downloads" (default on) applies after restart.
